Getting startedAuthentication

Every request carries a bearer token in the Authorization header:

Authorization: Bearer mh_<secret>

Create tokens under Settings → API tokens. The secret is shown once at creation — only a SHA-256 hash is stored. Each token has:

  • Scope — read (GET only) or write (read + create/update).
  • Workspace restriction — all workspaces, or a chosen subset.
  • Optional expiry — expired tokens return 401, just like revoked ones.

Revoke a token in Settings; revocation takes effect immediately.

ScopingWorkspaces

All content is partitioned by workspace. Collection endpoints (list & create) take a ?workspace=<uuid> query parameter:

  • A token restricted to exactly one workspace → the param is optional (that workspace is the default).
  • Otherwise the param is required (400 without it).
  • A workspace outside the token's restriction → 403; an unknown id → 404.

Discover ids with GET /api/v1/workspaces. By-id endpoints (get / update) don't take the param — the row's own workspace is checked against the token, and a row outside the allowed set returns 404 (indistinguishable from missing, so nothing leaks).

▸ Workspace feature toggles are enforced. A resource group disabled for a workspace (Settings → Workspaces) returns 403 { "error": "<feature> is disabled in this workspace" }. Tasks are always on.

ShapeConventions

  • Lists return { items: [...] }; single rows return { item: {...} }.
  • Successful creates return 201.
  • Dates are ISO 8601; day-scoped fields (dueDate, deadline) are YYYY-MM-DD.
  • Errors are always { "error": "<message>" } — see Errors.

EndpointsTasks

Tasks

action items — the core unit
GET /api/v1/tasks?workspace=&status= status: open (default), done, or scheduled (snoozed / not-yet-due recurring).
POST /api/v1/tasks?workspace= Create a task.
GET /api/v1/tasks/:id
PATCH /api/v1/tasks/:id Partial update; returns { item, next } — next is the spawned recurrence, else null.
POST /api/v1/tasks/:id/complete Mark done; same { item, next } shape (completing a recurring task spawns the next occurrence).

Task fields

contentRequired on create.
dueDateYYYY-MM-DD.
projectIdGroup under a project.
milestoneIdMust belong to the same workspace / project.
priority1 high, 2 medium, 3 low; null clears.
ownerNameMarks the task as waiting-on someone.
recurrenceUnitday · weekday · week · month · year, with recurrenceInterval.
snoozedUntilHide until a date.
statusopen / done.

Example

# List open tasks
curl -H "Authorization: Bearer mh_..." \
  "https://<host>/api/v1/tasks?workspace=<uuid>"

# Create
curl -X POST -H "Authorization: Bearer mh_..." \
  -H "Content-Type: application/json" \
  -d '{"content": "Send the follow-up", "dueDate": "2026-07-20", "priority": 1}' \
  "https://<host>/api/v1/tasks?workspace=<uuid>"

# Complete (recurring tasks return the spawned next occurrence)
curl -X POST -H "Authorization: Bearer mh_..." \
  "https://<host>/api/v1/tasks/<id>/complete"

ReferenceErrors

All errors share the shape { "error": "<message>" }.

StatusMeaning
400Invalid or missing fields, missing workspace param, or a cross-workspace projectId / milestoneId.
401Missing, malformed, revoked, or expired token.
403Write with a read-only token, a disallowed workspace, or a disabled feature.
404Row missing or outside the token's workspaces — no existence leak.
413Request body over 1 MB.

ReferenceLimits (v1)

  • No pagination — lists return everything in the workspace (fine at single-user scale).
  • No DELETE endpoints.
  • Note / meeting-notes PATCH is last-write-wins — no optimistic-concurrency check; the web editor's conflict handling doesn't apply to API writes.
  • Note attachments are set at create only; there are no attach / detach endpoints.
  • No rate limiting (single-user; to be revisited if that changes).
Separate surface Different auth, one job — not part of /api/v1.

Ingest APIPush generated notes

A single endpoint an external client uses to push AI-generated meeting notes into Meeting Hub — for example a meeting recorder or transcription tool that produces a summary and wants it to land next to the matching calendar meeting. It's purpose-built for that one job, and is separate from the scoped-token /api/v1 API above.

Authentication

A single static bearer token — not the per-user mh_ tokens. Configured server-side as INGEST_API_KEY; never hard-code it. Requests without a valid key get 401.

Authorization: Bearer <INGEST_API_KEY>

Ingest APIThe endpoint

POST

/api/ingest

one meeting per request · application/json
Pushes generated notes for one meeting. Batch by making multiple calls.

Request body

sourceId reqStable id for the meeting. For iCal-feed meetings this must be the iCal UID of the event; for a client-only meeting, use the client's own stable id. This is the join key.
notesGenerated reqThe generated notes. Markdown recommended — headings, lists, - [ ] checkboxes, code all render live.
titleMeeting title. Only used when the meeting isn't matched yet (shown in the review inbox).
startTimeISO 8601. Like title, only used for the unmatched case.
workspaceThe client's workspace name (e.g. "Work"). Matched case-insensitively to route the push; an unknown name never fails it — it just lands untagged for review.

Ingest APIMatching behavior

  1. Meeting Hub looks for a meeting whose calendar_event_id or external_ref equals sourceId (across all workspaces; a workspace hint breaks ties).
  2. Matched → writes notesGenerated into that meeting's generated-notes field, but only if it's currently empty — it never overwrites notes already there. → 200
  3. No match → the push is staged in the Incoming notes review inbox, where you match it to a meeting or create one. → 202
▸ Idempotent & safe to retry — re-sending the same sourceId never duplicates or clobbers. Once you resolve a pending push, Meeting Hub remembers the sourceId on that meeting (external_ref), so future pushes auto-match.

Ingest APIResponses

StatusBodyMeaning
200{ "matched": true, "meetingId": "…", "written": true }Matched and written.
200{ "matched": true, "meetingId": "…", "written": false }Matched, left unchanged (field already had notes).
202{ "matched": false, "pending": true, "pendingId": "…" }No match; queued for review.
400{ "error": "…" }Missing / invalid sourceId or notesGenerated.
401{ "error": "unauthorized" }Bad or missing bearer token.
413{ "error": "payload too large" }Body over the limit — default 5 MB; raise INGEST_MAX_BODY_KB server-side.

Example

# Calendar-sourced meeting — send the iCal UID
curl -X POST https://<your-host>/api/ingest \
  -H "Authorization: Bearer $INGEST_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "sourceId": "040000008200E00074C5B7101A82E008...",
    "notesGenerated": "## Summary\n\n- Decided X\n- Action: follow up with Y"
  }'

# Client-only meeting — no iCal UID, so send your own id + metadata
curl -X POST https://<your-host>/api/ingest \
  -H "Authorization: Bearer $INGEST_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "sourceId": "ext_meeting_8f2a",
    "title": "Ad-hoc sync",
    "startTime": "2026-06-30T18:00:00Z",
    "notesGenerated": "## Notes\n\n..."
  }'
